# Shimaenaga 配色仕様・本体反映版

2026-10-24。「静かな基本色に、役割のある少数のアクセント」を基準とする。
[定義範囲](highlight-scope.md) に沿った採用配色をテーマ本体へ反映した。
実際の検証と保留項目は [検証記録](verification.md) を参照。

## 1. 色と構文の役割

雪夜の基本アクセント8色は維持し、演算子だけ桜色を紫寄りにした専用色を使う。流氷はプレビュー確認後の要望に合わせ、少し深みのある青白を背景に使う。通常の構文は太字・斜体にしない。
従来構文・Treesitter・LSP の情報源が異なっても、意味が同じ要素は同じ色を使う。

| 役割 | 色 | 雪夜 | 流氷 |
| --- | --- | --- | --- |
| キーワード、制御構造、修飾子 | ラベンダー | `#8f91e0` | `#5146c7` |
| 関数、メソッド、組み込み関数 | 摩周ブルー | `#3c9ee3` | `#005cad` |
| 型、組み込み型、クラス、インターフェース、型引数、名前空間 | 青い池 | `#23b4a9` | `#00756b` |
| 文字列、文字 | エゾマツ | `#99a921` | `#526700` |
| 数値、真偽値、定数、列挙値、null / nil / None | カエデ | `#e77121` | `#a63f00` |
| 演算子 | 紫寄りの桜（雪夜） | `#d478d2` | `#b51070` |
| エスケープ、属性、デコレーター、プリプロセッサ、マクロ | 桜 | `#e277aa` | `#b51070` |
| 警告、TODO、操作中の強調 | イチョウ・カラマツ | `#cc9e07` | `#785800` |
| エラー、失敗、削除 | ナナカマド | `#f84e4e` | `#b80018` |

流氷の改訂は、各アクセントの輝度を下げ、HSL彩度を維持または高めたもの。
元から彩度が最大の色は最大のまま濃くしている。非透過の背景とのコントラスト比は、
元の白では8色とも約5.3〜6.5:1、採用背景では約4.6〜5.7:1。色同士の区別と透過時の見え方は実表示で確認する。
アクセント調整時の役割を維持し、背景は後に採用した落ち着いた白へ更新している。

型名と値の定数は区別する。Ruby のクラス参照は型、値の定数はカエデ。
組み込みという理由だけで関数を型色に変更しない。LSP の defaultLibrary でも役割を維持する。
変数・引数・プロパティ・self / this / cls はすべて基本文字色を使う。

### 基本色・補助色

| 用途 | 雪夜 | 流氷 | 扱い |
| --- | --- | --- | --- |
| 基本文字 `fg` | `#a8b6b7` | `#3d5067` | 変数・引数・プロパティ |
| 補助文字 `fg_dark` | `#8d9ba0` | `#50647a` | 区切り・非アクティブ・スキップ |
| 括弧 | `#da7f3f` | `#914215` | `blend(orange, fg, 0.20)`。数値より彩度を抑えたカエデ系 |
| コメント | `#7d8f92` | `#566a7f` | 本文より控えめな色・斜体 |
| 本文背景 `bg` | `#070c17` | `#e3eaf2` | 雪夜は深い紺、流氷は少し深みのある青白 |
| バー・サイドバー背景 `bg_dark` | `#111b2f` | `#d4deea` | 非透過表示用 |
| メニュー・表紙・フロート `bg_menu` | `#0b1221` | `#d4deea` | 流氷は `bg_dark` を継承 |
| 現在行・コード領域 `bg_highlight` | `#19253d` | `#cbd8e8` | 採用した現在行・コード背景 |
| 枠・区切り線 | `#3f484f` | `#a9b4c1` | `blend(bg, fg, 0.35)` |

コメントとテーマ背景の相対輝度によるコントラスト比は、雪夜が約5.79:1、流氷の採用背景では約4.60:1。
流氷の旧配色 `#657488` / `#e9eef5` では約4.09:1だった。深めの背景と文字色を正本パレットと本体に反映済み。
この計算は非透過の色同士の比較であり、壁紙・Blur・端末透過を含めた可読性の保証ではない。

### 文書・装飾

- 見出しはラベンダー・太字。レベルごとの虹色化はしない。
- リンクは摩周ブルー・下線。文書の強調・斜体は文書の意味に従う。
- コード領域は `bg_highlight` を使う。中のコードは構文の役割を維持する。
- 非推奨は補助文字色と取り消し線。診断は severity の色と下線を使う。
- `{}`・`()`・`[]` はカエデ色に基本文字色を20%混ぜ、数値より彩度を抑えて構造を示す。
- `,`・`.`・`:`・`;` は補助色、演算子は雪夜のみ紫寄りの桜色として数値のカエデと区別する。
- TypeScript の `type` はキーワード色、型名は青い池、定義を囲む `{}` は括弧色にする。
- Solarized Osaka の `@punctuation.bracket` をオレンジで示す考え方を採用する。構文用の赤は追加しない。
- プレビューでは明示的に記号として分類した部分だけに括弧色を付ける。文字列・コメント内の括弧は着色し直さない。

### 流氷の背景比較候補

白のまぶしさを抑える案として、青みのある深めの白を採用した。
プレビューの **b** で元の白と切り替える。初期値は深めの白とする。

| 用途 | 元の白 | 採用した深めの白 |
| --- | --- | --- |
| 本文背景 | `#f6f9ff` | `#e3eaf2` |
| フロート・サイドバー | `#e9eef7` | `#d4deea` |
| 現在行・コード領域 | `#e2e9f6` | `#cbd8e8` |

文字・アクセントは同じにし、選択・検索・差分・枠の派生色は選択した背景から再計算する。
本体と下表は採用した深めの白を基準にする。元の白は比較用に残す。
コメントと背景のコントラストは採用配色で約4.60:1。透過時は実表示で確認する。
透過中の通常面には端末の背景が見えるため、背景そのものの比較は **t** で非透過にして行う。
この比較機能は端末や Omarchy の背景・透過率を変更しない。

## 2. 操作状態と派生背景

| 状態 | 前景の役割 |
| --- | --- |
| エラー・失敗・削除 | ナナカマド |
| 警告・部分成功・TODO | イチョウ・カラマツ |
| 情報・変更・実行中 | 摩周ブルー |
| ヒント | 青い池 |
| 成功・追加 | エゾマツ |
| スキップ・無効・非アクティブ | 補助文字色 |

差分の本文は基本文字色を保ち、背景で区別する。サイン・状態ラベルは上表の前景色を使う。

`blend(bg, accent, amount)` は各 RGB チャンネルについて
`floor(bg + (accent - bg) * amount + 0.5)` とする。アルファ値を設定する処理ではない。

| 用途 | 混合 | 雪夜の背景 | 流氷の背景 | 文字・装飾 |
| --- | --- | --- | --- | --- |
| 選択、補完の選択行 | 青22% | `#132c44` | `#b6cee5` | 基本文字色 |
| 通常の検索一致 | 黄22% | `#322c13` | `#d0cdbf` | 基本文字色 |
| 現在の検索一致、評価時の強調 | 黄色そのもの | `#cc9e07` | `#785800` | テーマの `bg` 色、太字 |
| 追加行 | 緑12% | `#191f18` | `#d7ded8` | 基本文字色 |
| 変更行 | 青12% | `#0d1e2f` | `#cddcec` | 基本文字色 |
| 削除行 | 赤12% | `#24141e` | `#e3d1da` | 基本文字色 |
| 文字単位の変更 | 青24% | `#142f48` | `#b1cbe4` | 基本文字色 |

評価時の強調はプレビューでは固定した見本を表示する。実際の flash / fade の時間やアニメーションは今回変更しない。

## 3. 透過・バーの表示

透過表示では本文・サイドバー・フロート・補完の通常面の背景を付けない。
非透過表示では本文に `bg`、サイドバーに `bg_dark`、フロート・補完・メニュー・起動時の表紙に `bg_menu`（未定義なら `bg_dark`）を使う。
枠は派生した境界色を使い、周囲と同じ背景方針にする。

選択、検索一致、差分、現在行、コード領域、評価時の強調には識別用背景を残す。
診断下線、エラーや警告の文字色だけを理由に通常面全体を塗らない。

タブ・ウィンドウバーの通常面は透過表示では背景を付けず、非透過では `bg` を使う。選択中のタブは摩周ブルー・太字で示す。
ステータスラインのLualineは、スクリーンショットに合わせた色付きの帯を採用する。
本文の透過とは独立して、a/z区画はモード色の背景と `bg` の文字、b/y区画は `fg_dark` の背景と `bg` の文字、c/x区画は `bg_dark` の背景と本文色を使う。
区画は Powerline の矢印（左右 `` / ``）で区切り、区画内は `` / `` を使用する。表示項目と並びは変更しない。

| モード | 文字色 |
| --- | --- |
| Normal | 摩周ブルー |
| Insert | エゾマツ |
| Visual | 桜 |
| Command | イチョウ・カラマツ |
| Replace | ナナカマド |
| 非アクティブ | 補助文字色 |

上表のモード色はLualineでは背景色として使用し、文字は `bg` 色・太字で表示する。
Lightlineの既存の透過方針は維持する。Omarchy の透過率・Blur・壁紙と端末設定は変更しない。
「リファクタリング優先度」の任意配色は別の仕様として後続で扱う。

## 4. 専用プレビュー

```sh
nvim --clean -c 'luafile ~/Projects/shimaenaga.nvim/scripts/color-preview.lua'
```

- **Tab**: 雪夜／流氷。初期表示は雪夜。
- **t**: 透過／非透過。初期表示は透過。
- **b**: 雪夜では `#090f1c` / `#070c17` / `#050910` を循環。流氷では元の白／落ち着いた白を切り替える。
- **[ / ]**: サンプルを前／次へ。先頭と末尾は循環する。
- **`:q!`**: 終了。

11ページ: パレットと役割、TS/TSX、Python、Ruby、Rust、Go、Lua、Lean、SuperCollider、
文書・設定、UI と操作状態。スクロールして全体を確認できる。

構文は役割を明示した文字列を専用ハイライトで着色する。パーサー・LSP・追加プラグインは不要。
プレビューは本体と同じ正本パレットと `design.lua` を読み取り、比較用の背景だけを切り替える。テーマローダーや既存テーマの描画処理を呼ばない。
ハイライトはプレビューのウィンドウ専用 namespace に置き、既存のテーマグループは書き換えない。
起動した Neovim 内では表示オプションを設定するため、上記の `--clean` による別セッションで使う。

補完・infoview・post window・バー等は配色の見本であり、実プラグインの画面ではない。
評価・音声再生・Lean サーバーの起動も行わない。
この見本は41パーサー・全プラグインの実機確認を代替しない。

## Oilの部分的な背景の統一

Oilの一覧・非アクティブ面・枠・タイトル・ウィンドウバーを専用グループでメニュー面へ統一する。
